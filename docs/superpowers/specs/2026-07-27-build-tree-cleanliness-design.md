# Build Tree Cleanliness Design

**Status:** Approved

**Date:** 2026-07-27

**Authority:** This design is a narrow corrective amendment to approved specification
`002-nextjs-openai-agent-demo` and the existing CI contract. It does not change product behavior,
runtime modes, deployment behavior, dependency versions, DataHub or OpenAI boundaries, or
artifact contracts.

## Problem

The tracked `next-env.d.ts` file does not match the declaration file generated by the pinned
Next.js `16.2.11` toolchain. A production build therefore rewrites the tracked file by adding the
generated route-types import and the standard Next.js notice. Existing verification runs restore
or ignore this mutation instead of removing its cause.

The CI workflow starts from a clean checkout and runs the production build as part of
`pnpm verify:offline`, but it does not verify that the repository remains clean afterward.
Consequently, build-time mutations of tracked files or unexpected non-ignored generated files can
pass CI unnoticed.

## Chosen Approach

1. Replace the tracked `next-env.d.ts` content with the exact stable declaration content generated
   by the pinned Next.js toolchain:

   ```ts
   /// <reference types="next" />
   /// <reference types="next/image-types/global" />
   import "./.next/types/routes.d.ts";

   // NOTE: This file should not be edited
   // see https://nextjs.org/docs/app/api-reference/config/typescript for more information.
   ```

2. Add a focused smoke contract that protects the canonical declaration content and proves that
   the CI workflow contains a repository-cleanliness gate after the offline validation gate.
3. Add one CI-only step after `pnpm verify:offline` that fails when Git reports:
   - any tracked working-tree mutation;
   - any staged mutation; or
   - any untracked file that is not excluded by `.gitignore`.
4. Keep the ordinary local `pnpm build` and `pnpm verify:offline` commands unchanged. Developers may
   continue to build from a working tree containing intentional local changes; the absolute clean
   checkout requirement applies only to CI.

## Why This Approach

The full-tree gate protects the repository from the entire class of build and verification
residue, not only the currently observed `next-env.d.ts` symptom. Running it in CI avoids false
failures caused by intentional local edits while relying on the clean checkout already established
by `actions/checkout`.

The gate remains a separate workflow step instead of duplicating the production build or splitting
the established `verify:offline` command. This keeps the implementation small, preserves one
offline verification entry point, and still catches every persistent mutation because the build
occurs inside that command.

## CI Cleanliness Contract

The post-verification step will use Git itself as the authority:

```bash
git diff --exit-code
git diff --cached --exit-code
test -z "$(git status --porcelain --untracked-files=all)"
```

Ignored build output such as `.next/`, `dist/`, Playwright output, temporary run data, and local
environment files remains outside the check according to the existing `.gitignore` policy.

The check must not reset, delete, restore, or otherwise modify the checkout. It reports failure and
leaves the mutation available for diagnosis.

## Testing

Implementation will follow RED-GREEN TDD:

1. Add a focused smoke assertion for the exact canonical `next-env.d.ts` content and observe it fail
   against the current custom file.
2. Add a focused workflow assertion requiring the full post-verification Git cleanliness commands
   and observe it fail while the CI step is absent.
3. Apply the canonical declaration and the smallest workflow change.
4. Rerun the focused smoke test and observe both assertions pass.
5. Run a real production build from a clean test checkout and prove that the Git tree remains clean.
6. Run the affected suite and repository-required offline, formatting, diff, and secret-scanning
   gates.

## Acceptance Criteria

- `pnpm build` does not modify `next-env.d.ts`.
- The exact Next.js-generated declaration content is committed with LF line endings.
- CI fails after the offline gate when any tracked, staged, or non-ignored untracked residue exists.
- CI remains green when only ignored build and test outputs are generated.
- Local `pnpm build` and `pnpm verify:offline` behavior remains unchanged.
- The existing CI permission model, immutable action pins, frozen lockfile installation, and
  credential-free offline behavior remain unchanged.
- No dependency, lockfile, runtime, UI, API, deployment, DataHub, OpenAI, or artifact behavior
  changes.
